# Changelog

Newest first. One entry per PLAN or SPEC version, one per build merged, one per release. Bug fixes and operations
(live-data updates) are listed here too, not in `DECISIONS.md`.

**Format:**
- Heading: `## PLAN v<a> · SPEC v<b> · <date> (<trigger>)`.
- The trigger is a review file, a spike, a decision, or a build merged.
- The bullets under it follow the example below.

---

## PLAN v1.1 · SPEC v1.1 · <date> (panel: `work/R/reviews/SUMMARY.md`)

Every ID below was accepted by <owner>. Loosening items (⚠) were confirmed separately (D-0xx).

- **M07 ⚠** <one-line change>. *SPEC §2.*
