# Changelog

Newest first. Write one entry per PLAN/SPEC version bump and one per phase close (L-20).

**Format:**
- Heading: `## PLAN v<a> · SPEC v<b> · <date> (<trigger>)`.
- The trigger is a review file, a spike, a decision, or a phase close.
- The bullets under it follow the example below.

---

## PLAN v1.1 · SPEC v1.1 · <date> (Phase R: `reviews/SUMMARY.md`)

Every ID below was accepted by <owner>. Loosening items (⚠) were confirmed separately (D-0xx).

- **C01** <one-line change>. *PLAN §6B; SPEC §7.2, §13.3.*
- **M07 ⚠** <one-line change>. *SPEC §2.*

## Phase <n> closed · SPEC v<b> · <date>

- Delivered: <one line>. Tests: <count>. Audits: P<n>-SA1 <C/M> → … → 0/0. Code review: P<n>-CR1 <C/M>.
- Rules changed: <IDs and SPEC sections, or "none">.
- Decisions: <D-IDs>.
